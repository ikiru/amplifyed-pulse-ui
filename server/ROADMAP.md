# AmplifyEd Product Roadmap
**Status:** Active • Contract-Driven • Safety-First

This roadmap reflects **locked decisions**, **explicit boundaries**, and **intentional sequencing**.  
Phases only unlock when their contracts are complete.

---

## Phase 0 — Foundations & Architecture
**Status:** Complete (Locked)

**Intent:**  
Establish a stable technical and conceptual foundation.

**Included:**
- Core socket architecture
- Pipeline separation (pulse, message, safety, emotion, session)
- Event routing
- Baseline anonymity guarantees

**Locked:**  
No re-architecture without reopening Phase 0 explicitly.

---

## Phase 1 — Baseline UI & Interaction Surfaces
**Status:** Complete (Locked)

**Intent:**  
Establish minimal TrainerView and AudienceInput surfaces.

**Included:**
- Initial page layouts
- Core component boundaries
- Routing between TrainerView and AudienceInput

**Excluded:**
- Meaning
- Safety semantics
- Interpretation

---

## Phase 2 — Pulse System Stabilization
**Status:** Complete (Locked)

**Intent:**  
Create a reliable, mathematically stable pulse signal.

**Included:**
- Pulse submission logic
- Pulse aggregation
- Pulse normalization
- Broadcast stability

**Excluded:**
- Emotional interpretation
- Engagement evaluation

---

## Phase 3 — Emotional Engine
**Status:** Complete (Locked)

**Intent:**  
Define how emotional signals are processed **without assigning meaning to people**.

**Included:**
- Emotional signal extraction
- Smoothing and trendlines
- Envelope normalization

**Guardrail:**  
Emotion exists as signal, not diagnosis.

---

## Phase 4 — Governance & North Star Lock
**Status:** Complete (Locked)

**Intent:**  
Formally lock system ethics and constraints.

**Included:**
- Psychological safety principles
- Audience-first design constraints
- No-surveillance posture
- No evaluative language posture

---

## Phase 5 — Meaning Layer Contract
**Status:** Complete (Locked)

**Intent:**  
Define **what the system is allowed to mean**.

**Included:**
- Signal vs interpretation boundaries
- Meaning suppression rules
- Trainer awareness limits

**Critical Rule:**  
The system may surface **signals**, never **judgments**.

**Excluded:**

## Phase 8 — Session Lifecycle UX
**Status:** Complete (Locked)

### Phase 8.1 — Session Access UX
- Join code + QR
- Required presence without coercion
- No onboarding, no confirmation, no completion UX

### Phase 8.2 — Live Session Presence & Safety
- In-flow UX
- Safety exception interrupts
- Trainer awareness without evidence

### Phase 8.3 — Engagement Without Pressure
- “Invited into play” posture
- No prompts disguised as requirements

### Phase 8.4 — Re-entry & Continuity
- Audience rejoin after device loss
- Trainer rejoin after crash
- Message continuity

### Phase 8.5 — Exit & Closure
- Silent exits
- No completion states
- No summaries

**Status:** Complete (Locked)

**Intent:**  
Define what is **never** remembered.

**Included:**

## Phase 12 — Safety Governance & Incident Continuity
**Status:** Planned (Post-UX, Post-Meaning)

**Intent:**  
Define how high-risk safety events are sealed, governed, and accessed **outside live sessions**, without altering participant experience.

**Included:**
- Safety event classification thresholds
- Sealed report posture
- Role-based access governance
- Organizational handoff boundaries

**Explicitly Excluded:**
- Live UX changes
- Audience-visible records
- Trainer adjudication tools
- Surveillance or scoring

**North Star Guardrail:**  
No live surface may render or imply evidentiary artifacts.
